Analisis Bottleneck

Bottleneck #1: Port-Forward Goroutines

kubectl port-forward adalah proses Go single-process dengan kapasitas ~150 goroutine simultan. Setiap request /api/courses butuh ~3100ms, mengikat goroutine selama itu. Pada 500 users, antrian goroutine habis -> request timeout -> failure ~36%.

Bukti: Static endpoints (/, /tugas.html, /health) butuh hanya ~4ms dan memiliki 0% failure. Ini membuktikan port-forward mampu menangani traffic, tapi goroutine tersumbat oleh request lambat.

Bottleneck #2: CPU Sidecar (ProcessPoolExecutor)

Sidecar hanya memiliki max_workers=4 dengan CPU limit 400m. 15.000 SHA-256 rounds per request membutuhkan waktu signifikan. Dengan tunnel, HPA bisa scale-up pod untuk menambah worker paralel.

Mengapa HPA Tidak Terlihat Efeknya?

Bottleneck ada di port-forward (sebelum traffic masuk klaster). HPA scale-up menambah pod, tapi request tetap harus antri di port-forward yang hanya punya ~150 goroutine. Ibarat memperlebar jalan tol (HPA) tapi pintu masuknya tetap selebar 1 jalur (port-forward).

Prediksi Kinerja dengan Tunnel

Jika bottleneck port-forward dihilangkan via minikube tunnel:

  • Static endpoints: 5.000+ RPS (dari ~78 RPS saat ini)
  • /api/courses tanpa HPA: tetap tinggi (~3000ms, 30-60% failure) karena 1 pod kewalahan
  • /api/courses dengan HPA: 200-800ms, 0-5% failure — beban terdistribusi ke 4-10 pod
  • Perbedaan signifikan antara Tanpa HPA vs Dengan HPA akan terlihat jelas
